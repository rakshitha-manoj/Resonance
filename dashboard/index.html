Help: inputs, format and limits
  • Link to a replay. index.html?replay=demo_events_sim.jsonl&speed=20 plays that file at 20x as soon as the page opens (optional &at=end or &at=250 (seconds into the log) or &at=sf235 to start paused at that moment). The bundled demo_events_sim.jsonl is also embedded in this page, so it works from file:// too; any other file name needs the page to be served (python -m http.server in dashboard/) because Chrome does not let a file page read other files.
  • Replay. Open a JSON-lines log (first line meta; then begin/change/status events, schema 2 also one sample line per superframe, restart lines, and node lines for an immediate sensor DEAD/ALIVE change). Schema 1 logs (events only) still work. Playback runs on the t_us clock in the file: 1x is real time, 10x and 60x are faster. Events are logged only when the class changes (and as a periodic status); schema 2 samples fill the gaps, so the chart, the sensor "last report" and the calibration progress are continuous.
  • Damage demo (simulated). Plays demo_events_sim.jsonl, made by the PC network simulator (netsim) from the project's firmware code: a simulated 10-storey building, sensors on floors 5 and 10, a local impact, a building-wide event, a frequency shift on one sensor and finally a permanent 30 % stiffness loss in storey 1 (natural frequency about 4 % lower). The page reads the file from its folder when it can, otherwise it uses the copy embedded in the page.
  • Panels. Std ratio r (vibration level / own baseline, threshold T) and AE ratio (int8 autoencoder reconstruction error / own baseline, threshold T_ae) are the two detectors of rule f (an event if EITHER fires, each smoothed 2-of-3). The natural-frequency panel shows each sensor's f1 estimate against its own commissioned f1_0 with a band of plus/minus the DAMAGE threshold; the DAMAGE banner turns red after the pooled f1 drop has stayed at or above the threshold for P superframes.
  • Live over USB. Chrome or Edge on a desktop only (Web Serial API), 115200 baud. Close any other program using the port first (PlatformIO or Arduino serial monitor). The master firmware prints the same JSON lines as the simulator; the page keeps lines that are JSON objects of the schema and ignores everything else, including the R, and S, CSV lines and # comments. If the master reboots, its clock starts again at 0; a restart line marks it and the page continues the timeline after the last line.
  • MQTT live (cloud). The master (or tools/sim_publisher.py, or the Wokwi cloud demo) publishes the same JSON lines to an MQTT broker under resonance/<site>/<type>; this page subscribes over MQTT-over-WebSocket (default: the free public HiveMQ broker, site id from the firmware config) and feeds each message through the same parser as the other sources. Anybody who knows the site id can read a public broker's topics, so use it for simulator or demo data only; a private broker with TLS and a password works by changing the URL and the options. The retained meta arrives at once, so a page that joins late still knows the floors. The counters show messages received and lines dropped (malformed or buffer full); lines the master or the broker dropped are only visible in the master's S,mqtt statistics. Cross-topic arrival order is not guaranteed by MQTT: the page re-sorts by time. Browser notifications (permission asked when you click "Enable notifications") fire for new begin events, sensors going offline and the DAMAGE alarm starting or clearing. Needs vendor/mqtt.min.js (MQTT.js, MIT); without it the rest of the page works as before.
  • Demo. A short scripted scenario written to follow schema 2 exactly. It is not hardware data and not simulator output.
  • Not available: r values between logged lines in schema 1 logs, and the age of a sensor's last report in schema 1 logs. These show as "not available".
  • Limits. Replay, demo and USB run entirely offline; nothing leaves your computer. Only the "MQTT live" source connects to a broker (and only when you click connect).

Std ratio r1, r2 (detector b)

    
    
r = vibration level (az standard deviation) divided by that floor's normal (baseline) level; an event if r reaches T. A point every superframe (about 1.4 s) in schema 2/3 logs; schema 1 logs only where an event was logged. Hover or touch the chart to read a value.

  


  
TinyML autoencoder ratio (detector e)

    
    
AE ratio = reconstruction error of the int8 autoencoder on each sensor divided by its own commissioning level; an event if it reaches T_ae. It catches what the std ratio misses: frequency shifts and sparse impacts. Shown clipped at 6 x T_ae.

  


  
Natural frequency f1 per sensor

    
    
Solid = f1 estimate (Hz) of each sensor, thin line = its commissioned f1_0, shaded = f1_0 minus/plus the DAMAGE threshold. A sustained drop below the band is the damage signature.

  


  
Pooled f1 drop (DAMAGE input)

    
    
Pooled drop = mean of the sensors' (f1_0 - f1) / f1_0 in percent. DAMAGE begins after it stays at or above the threshold for P consecutive superframes and ends after P below half of it.
