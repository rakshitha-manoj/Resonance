# Resonance structure

Edge structural health monitoring: ESP32 + MPU6050 classifies vibration as normal / abnormal / faulty.
Targets: >=90% accuracy, <50 ms inference, model <100 KB.

- `src/main.cpp` – live inference: 10 ms micros() deadlines, DLPF 42 Hz, boot read-back of DLPF/accel/gyro config (`config fail` halts), buffers az+gx (128 each, non-overlapping, schedule re-anchored after each window), 2-of-3 smoothing, prints `window,class,state,feat_us,tree_us,span_us`. (Phase 1 raw CSV streaming is in git history.)
- `src/selftest.cpp` – boot self-test: 606 embedded dataset windows (class + feature diffs, latency), then a 120-window scripted sequence (normal→faulty→normal→abnormal→normal→normal-with-isolated-error) checking raw class and smoothed state vs Python; ends `seq done PASS/FAIL`. Phase C2a: it also runs the FULL slave pipeline (`slave_pipe.h`: features_ex + bands + AE + zoom + f1 tracker + tree) over the 606 windows and prints `pipeline us ... -> FITS|EXCEEDS the 45 ms budget` and `pipeline class match`.
- `include/smooth.h` – `smooth_update(hist, raw, state)`: state becomes a class once it has 2 of the last 3 raw windows, else holds. hist starts {-1,-1,-1}, state 0.
- `include/features.h` – feat_std_kurt / feat_std / feat_domfreq (two-pass float32, direct DFT bins 1..64), `features()` computes only the 5 used features, `classify()`.
- `include/spectrum.h` (Phase 0 front-end, Arduino-free, C and C++11) – `spec_power` (= `feat_dft_power` of features.h: the az DFT bins 1..64, arithmetic of the old `feat_domfreq`, so argmax reproduces it bit-for-bit), `spec_bands` (16 x logf(sum of 4 bins + 1)), `spec_zoom` (mean-removed, Hann-windowed Goertzel power at 3.0..12.0 Hz step 0.05, 181 values, 23k MACs), `spec_peak` (argmax + parabolic interpolation in log power, edges/non-positive -> grid Hz). `features_ex(az, gx, f, az_p)` = `features()` plus the az power spectrum from the single az DFT (`features()` is a wrapper). Tables in `include/spectrum_tables.h` (GENERATED by `tools/gen_spectrum.py`: Hann window + Goertzel coefficients as hex floats, same on host and ESP32; parameters must match spectrum.h).
- `include/spectrum_tables.h` carries `SPEC_TABLE_*` parameters; spectrum.h `#error`s if they differ from its `SPEC_ZOOM_*` constants and checks table lengths at compile time. `spec_peak` skips NaN entries (all-NaN: f0).
- `tools/frontend_lib.c` – C source for the Python bridge (`front_batch`, `front_peak`), includes features.h + spectrum.h; built by `models/training/frontend.py`, not part of any PlatformIO env.
- `include/f1track.h` (Phase A, slave-side, Arduino-free, C and C++11, no heap) – `f1t_t` tracker, 23.4 KB: declare STATIC/GLOBAL, never on the 8 KB loop stack. Ring of the last M zoom spectra (mean recomputed every window), raw estimate = `spec_peak(mean)` (invalid on warm-up / grid edge / non-finite). Commissioning: `f1_0` = median (even: mean of 2 middle) of the last C valid raw estimates, only if unimodal ((p90-p10)/median <= `F1T_SPREAD_MAX` 0.10, else the window slides on); afterwards estimates outside f1_0 x (1 +- `F1T_BAND` 0.20) are INVALID (mode jump, post-hoc fix after verification found mode-2 locks on low floors of low-f1 buildings); `f1t_drop` = (f1_0 - f1_est)/f1_0 (NAN unless commissioned and valid); `f1t_not_commissioned()` = overdue after M + 4C windows (f1 outside 3-12 Hz, first mode invisible, unstable). `f1t_feed(raw)` is the gating step on its own (used by the bridge on cached estimates). Defaults `F1T_M=32`, `F1T_C=64` = the selection in `freq_tracking.json` (test_shm `test_chosen_constants` fails if header and JSON differ; `-DFREQ_JSON` in the `native` env). A low floor can commission onto mode 2 consistently and then track mode 2, not f1.

## Network behaviour (R1) – read before touching tiers.h
- Master epoch: `Master::reset(start_us, epoch)` takes a boot epoch (random on hardware, e.g. `esp_random()`, different from the previous boot; PRNG in the simulator). It is carried in every BEACON, POLL and REPORT. The master drops reports of another epoch (`rx_epoch`); a slave answers only polls of its current epoch.
- Slave sync rules: power-on or LOST => any CRC-valid beacon is accepted. Synced and epoch changed => resync at once (new epoch, window in progress abandoned, cached report discarded; smoothing history, smoothed state and window counter are KEPT because they describe the slave's own sensor, so the first post-restart report is just window N+1). Synced, same epoch => `sf` must be in (last, last + `MAX_SF_JUMP`], `MAX_SF_JUMP` = 8 = `MAX_MISSED_BEACONS` + 3 (free-running advances last_sf, so a legitimate beacon is at most +1; 8 leaves slack yet keeps one stray CRC-valid beacon from locking a slave out); sf == last right after a free-run is a late beacon (timing re-aligned, running window kept; the window keeps UNSYNCED, because it was started on the slave's own timing and the flag is the only field evidence for tuning BEACON_GRACE_US). A CRC-valid forged beacon with a new epoch is adopted, but the real master's next beacon changes the epoch again and resyncs the slave.
- Restart recovery (simulator, lossless): first fresh report 1.32-1.33 s after the master restarts (within one superframe; every restart offset within 0.95 superframes in re-verification), no stale report accepted. 20% loss: usually within 2 superframes, but the tail is longer: 1.6% of 1600 slave-runs took 3 or more, worst about 7 superframes (~9.7 s), because a lost first beacon after the restart leaves the slave free-running in the old epoch. No foreign-epoch or stale report was accepted.
- Epoch reuse: if a restart reuses the previous epoch, the slaves see an sf far behind theirs and reject beacons until they go LOST (about 6 superframes outage, DEAD/ALIVE events, no stale data). The `Master` constructor uses epoch 0, so real firmware MUST call `reset(..., e)` with `e = esp_random()` taken after Wi-Fi start, rejecting 0, never a timer-derived value.
- Window token API: `uint32_t token = take_window_request()` (non-zero; 0 = nothing requested), `window_start()`/`window_sf()` for the window's first-sample time and superframe, `bool deliver_window(token, az, gx, now)`. A window abandoned by a later beacon or by `reset()` has a different token (the counter survives `reset()`), so its late delivery is rejected (`windows_rejected`) and changes nothing.
- Master beacon schedule: fixed grid (`next_beacon_ += SUPERFRAME_US`), not `now + period`, so tick lateness does not accumulate (mean period stays 1.4 s). If a tick is a whole superframe or more late the master sends one beacon, jumps to the next grid point after now and counts the skipped points (`beacons_skipped`); the superframe number advances by the skipped points too, so it stays equal to the grid index and stays in step with slaves that free-ran through the stall (without this, a 2.8-8.5 s master stall made the slaves reject its beacons as stale: false DEAD on both, or a stale report accepted; `test_sim_master_stall` covers 0.5-9 s stalls). Polling start is still `beacon time + 1.32 s`. Measured with the master woken 0-8 ms late on every wakeup (1500 superframes): mean period 1,400,000.2 us, 3000/3000 reports, no DEAD, no overrun; BEACON_GRACE_US (5 ms) is below that lateness, so 7.8% of windows start via a false free-run (at most ~3 ms from the beacon transmission in re-verification; harmless to classification) and all of them arrive flagged UNSYNCED. Real tick lateness should be well under 5 ms; measure on hardware.
- Report validation at the master: raw class or state outside {0,1,2}, reserved flag bits (6, 7), non-finite feature => `rx_bad_field` (core fields: the whole report is rejected). OPTIONAL version-3 fields (`report_sanitize`, applied after the core check, again inside `Fusion::on_report`): AE_READY with a non-finite or negative ae_ratio => the flag is cleared and `rx_ae_bad` counts it; F1_VALID with a non-finite f1_est or one outside [0, 100] Hz => F1_VALID cleared; F1_VALID + F1_COMMISSIONED with a non-finite f1_drop or |drop| > 1 => F1_COMMISSIONED cleared (both count in `rx_f1_bad`); the report itself is KEPT, so rule b's az_std never depends on the AE or the tracker. Floats whose flag is clear are ignored, not checked. The ranges also bound the width of the JSON lines. Other rejections: source must be slave 1..2 (`rx_invalid`); a report is accepted only from a slave the master has polled in the current superframe (`rx_unpolled`; a late reply to an earlier poll of the same superframe is fine) and only while polling is open. Real MAC/authentication checks come in R5.
- Send failures: a failed `broadcast` is counted (`tx_failed`). Master: a failed poll counts as a used attempt and the retry / next slave follows immediately; a failed beacon makes the slaves free-run. Slave: a failed reply is counted, the master's retry asks again.
- Compute-time limits (timing constants are NOT to be changed before hardware measurements): slave 1's first poll fails above ~50 ms compute (~45 ms on the free-run path), and slave 1 is declared DEAD while healthy from ~68-70 ms; slave 2 tolerates ~100 ms. The measured on-device feature time (~24 ms in Wokwi) is inside this, but re-check on hardware.
- False DEAD: with the 3-miss rule and 2 attempts, a healthy slave is declared DEAD about 0.1 times per slave-hour at 10% i.i.d. loss and about 5 per hour at 20%, so the rule suits only low loss. R5 must measure real loss and its burstiness before choosing DEAD_AFTER_MISSES.
- Hardware notes for the ESP-NOW port: use a 64-bit clock (`esp_timer_get_time()`), never 32-bit `micros()` (wraps after 71 min and breaks the 64-bit deadline arithmetic); the ESP-NOW receive callback runs in the Wi-Fi task, so queue received packets to the main loop and call `on_packet` there, because the state machines are not thread-safe; check `Transport::broadcast`'s return value (esp_now_send queue full/error => false).

(2) With the tree-based rules a and d the old tree's false 'faulty' on healthy monitoring gives 8.9-38.2 false onsets/h even with k = 3; rule c (tree AND ratio) at T = 3 is eligible on dev (0.61/h at k = 1, mean recall 0.617, runner-up to b's 0.622; 0.11/h at k = 3) and is the post-hoc alternative (see the Results summary), so the ratio-only b and the tree+ratio c at T = 3 are the ones that meet 1/h. The price of meeting it: a sparse single impact is almost never caught (0.05) and a frequency shift only 0.32, and 2x events 0.44. Trade-off on development: under 0.5/h b/T3/k3 (mean 0.551); under 10/h b/T2/k3 (LOCAL 0.57, BUILDING 0.97, 6.9/h); under 20/h d/T2/raw/k3 (LOCAL 0.71, BUILDING 0.97, 15.5/h); under 60/h d/T2/raw/k1 (LOCAL 0.98, BUILDING 0.99, 55/h). (3) The dev false-onset estimate (0.79/h, about 22 onsets in 28 h) is noisy; test gave 2.04/h. (4) Simulator only (`building_sim`: uniform shear building, stationary band-limited excitation, modelled gx); the real frame is a small model, so ratios and thresholds must be re-measured. (5) The baseline assumes quiet commissioning; an event or a noisy first 20 windows biases it (nothing detects that). The ambient level of a healthy recording is drawn 0.5-1.5x of the commissioning level, so any real drift in ambient level moves the ratios directly. (6) An impact or shift on an uninstrumented floor is reported only: any LOCAL/BUILDING output in about 2% of those recordings. (7) A slave that is dead from boot keeps the system in COMMISSIONING forever (both baselines are required; COMMISSIONING takes precedence over NO_DATA/DEGRADED).
- Semantics (also the header comment of fusion.h; `RefFusion` in `models/training/fusion_eval.py` is the exact reference): a superframe closes when both slaves reported, or the master finished polling it (`advance(master_sf, polling_active)`), or a later superframe starts. Baseline = median of a slave's first `COMMISSION_WINDOWS` = 20 reports' f[0] (float32, mean of the two middle values); the superframe that completes the last baseline is still COMMISSIONING. One slave without a report (lost or DEAD) => DEGRADED(alive slave): only LOCAL(alive) or AMBIENT, LOCAL iff the rule's single-slave condition holds (a: F, b: e, c: F and e (r_other cannot be checked), d: F). Neither => NO_DATA. A missing slave's e history is held; it is cleared when the slave returns (ALIVE after DEAD). Baselines survive outages and master restarts; a superframe number below the next unclosed one is treated as a master restart (stream restarts, baselines kept); a jump over `MAX_CATCHUP_SF` = 32 is skipped, not replayed. Ratio denominator is max(baseline, `BASELINE_MIN` = 1.0). Reports with non-finite or negative f[0] are rejected (counted). Degraded-mode numbers: `fusion_eval.md` has those of R2's rule d (NOT the final rule); the final rule b's are in `models/selected/validation/compare_hierarchy.md` (dead-slave section: death declared after about 4.2 s, any-alarm detection with one slave dead, BUILDING never output).
- Events (emit only on change): an event is emitted when the key (class, local slave, degraded slave) differs from the previous superframe's, and for the first superframe. `begin` = LOCAL/BUILDING after a non-event class; every other change (event ends, LOCAL(1) -> LOCAL(2), LOCAL <-> BUILDING, DEGRADED / NO_DATA / COMMISSIONING transitions) is `change`. Every `STATUS_EVERY_SF` = 64 closed superframes (about 90 s) a `status` repeats the current decision. `t_us` = master clock at the call that closed the superframe (up to about 1.4 s after the window it describes).
- JSON-lines event log, **schema 3** (additive over schema 2 and 1; the schema-2 text below stays valid, the schema-3 additions are listed after it: a v1 reader that ignores unknown types and fields still works). Written by `netsim --events-jsonl` and printed by the master firmware on serial (one line each, same formatter `fusion_json.h`, byte-identical for the same input); the dashboard replays and live-reads it. Numbers: integers in decimal, floats with up to 7 significant digits and no exponent; `null` = unknown. Line types, in this order:
  - `meta` (first line; on hardware again at every boot): `{"type":"meta","schema":2,"source":"netsim"|"master","rule":"b","T":3,"use_raw":false,"debounce":1,"commission_windows":20,"status_every_sf":64,"superframe_s":1.4,"floors":[5,10],"epoch":2866824256,"samples":true}`. `floors` = physical floor of slave 1 and 2 (netsim: `--floors` or the `.floors` sidecar of the trace file, else 1,2; hardware: `SLAVE_FLOOR_1/2`, default 1,2). `epoch` = the master's boot epoch (null if unknown). `samples` = the log contains `sample` lines.
  - `restart`: `{"type":"restart","t_us":<uint64>,"epoch":<new>,"prev_epoch":<previous epoch | null>}`. netsim: whenever the simulated master restarts (kill + revive of node 0), `t_us` continues on the simulation clock. Hardware: printed once at every boot right after `meta` with `prev_epoch` null (the host cannot tell a first boot from a reboot) and `t_us` = time since boot, so a restart line after other lines means the master rebooted and `t_us` starts again at 0 (the dashboard continues its timeline after the last line). Fusion keeps its baselines across a restart in the simulator; on hardware a reboot loses them (RAM), so commissioning starts again.
  - `sample`, one per closed superframe (the debounced output, the same decision the events are made from; netsim default on, `--no-samples` off; hardware default on, `JSON_SAMPLES` 0 off, and dropped first when the serial buffer is short): `{"type":"sample","t_us":<uint64 master clock when the superframe was closed>,"sf":<uint32>,"class":"COMMISSIONING"|"AMBIENT"|"LOCAL"|"BUILDING"|"NO_DATA","slave":<1|2 for LOCAL else 0>,"degraded_alive":<0 | the one alive slave>,"r1":<az_std/baseline | null>,"r2":<...>,"alive":[<bool>,<bool>],"age":[<n1|null>,<n2|null>],"commission_n":[<n1>,<n2>],"closed":<superframes closed so far>}`. `age[i]` = superframes since slave i's last report (0 = it reported in this superframe, null = none since the stream (re)started). `commission_n[i]` = reports collected towards slave i's baseline (stays at `commission_windows` once the baseline exists). A sample comes before the event of the same superframe, with the same `t_us`.
  - `node` (additive, emitted at the moment the master's DEAD / ALIVE status of a slave changes, in both netsim and the master firmware, byte-identical formatter): `{"type":"node","t_us":<uint64 master clock>,"sf":<uint32 master's current superframe>,"slave":<1|2>,"state":"DEAD"|"ALIVE"}`. Before this line the log only showed a dead slave as `alive:false` on the next sample, event or periodic status (up to about 90 s with `--no-samples` / dropped samples), and `degraded_alive` also fires on a single lost report, so it is not a health signal. DEAD comes after 3 missed superframes (about 4.2 s). It precedes the sample / event of the superframe that closes right after it (same `t_us`). DEAD and ALIVE alternate per slave; a master restart (`restart` line, or a second `meta` on hardware) forgets the state, because a restarted master starts with both slaves alive. Fusion decisions do not depend on it (parity unchanged). Dashboard: immediate sensor Dead/Alive plus an event-history row; readers that do not know the type ignore it.
  - `begin` | `change` | `status` (events, as in schema 1, plus `commission_n`): `{"type":"begin"|"change"|"status","t_us":<uint64>,"sf":<uint32>,"class":...,"slave":<1|2 for LOCAL else 0>,"degraded_alive":<0 | the one alive slave>,"r1":<az_std/baseline or null if no report>,"r2":<...>,"base1":<float, 0 = unknown>,"base2":<...>,"alive":[<bool>,<bool>],"closed":<superframes closed so far>,"events":<begin+change events so far>,"commission_n":[<n1>,<n2>]}`. The class is the debounced output.
  - **Schema 3 additions** (Phase C2a): `meta` has `"schema":3`, `"T"` = the threshold of the std ratio r (what a reader draws on the r chart; rule f: T_b = 3), for rule f also `"T_ae"` (6, the AE threshold) and `"gate"` (counts), and always `"dmg_delta"` (0.02) and `"dmg_p"` (32); the rule letter may be `f`. `sample` and the events `begin`/`change`/`status` get, after `r2`, `"ae":[a1|null,a2|null]` (the slaves' AE ratio of this superframe, null = no report or AE not ready; shown at most 1e9), `"f1":[hz|null,hz|null]` (f1 estimate, null = no report or not valid), `"drop":[d|null,d|null]` ((f1_0 - f1)/f1_0, null = no report / not valid / not commissioned; positive = f1 fell), `"dmg":0|1` (DAMAGE state after this superframe). New line (non-sample, after the `sample` of the superframe in which the state flips, before that superframe's class event) `{"type":"damage","t_us":..,"sf":..,"state":"BEGIN"|"END","drop":<pooled drop of that superframe>,"f1":[hz|null,hz|null],"f1_0":[hz|null,hz|null]}`: `f1` = the slaves' estimates in that superframe (null = not contributing), `f1_0` = each slave's commissioned f1 derived on the master as `f1_est / (1 - f1_drop)` from its last usable report (null = never). BEGIN after P = 32 consecutive superframes with pooled drop >= 2 % (`dmg_delta`), END after 32 below 1 %; BEGIN and END alternate; a superframe with no usable slave holds state and counters; the state survives a stream restart in netsim, a master reboot loses it. Examples with lengths (bytes incl. newline): sample 262 (`{"type":"sample","t_us":132930238,"sf":94,"class":"LOCAL","slave":2,"degraded_alive":0,"r1":0.962903,"r2":4.106328,"ae":[0.9789,9.51167],"f1":[5.379312,5.384131],"drop":[null,0.0051035],"dmg":0,"alive":[true,true],"age":[0,0],"commission_n":[20,20],"closed":95}`), damage 105 (`{"type":"damage","t_us":131529754,"sf":93,"state":"BEGIN","drop":0.0205,"f1":[5.25,null],"f1_0":[5.4,6]}`), meta 255 (netsim, floors 5/10), begin event 292. Widest possible lines with a plausible-range Master filter: event 383, sample 355, damage 148, meta 276 (limit `JSON_LINE_MAX` 448; tested, and a hostile 3.9e18 in every float still fits). Validator and schema-3 rules: `dashboard/tools/validate_logs.py` (schemas 1-3). The dashboard draws all of it since Phase C2b (see "Phase C2b").
  - Schema 1 differences: meta has `schema:1` and no `source`, `floors`, `epoch`, `samples` (the first schema-1 files also lacked `debounce`), no `sample`/`restart` lines, no `commission_n`. Validator for all bundled logs (also the `node` line rules): `dashboard/tools/validate_logs.py`.
  - Firmware coupling: the new read-only callback `fusion::Sink::on_sample(const Sample&)` (called from `Fusion::finalize` after `on_decision`, before the event; it cannot change a decision, tested), `Event::commission_n`. (4) The DAMAGE state survives a stream restart in `Fusion` (it describes the structure); a master reboot loses it, like the baselines. **Contributor guard** (fusion.h): the state is defined by the slaves that contributed at the last transition; a member without a usable drop for 8 superframes holds the decision and restarts the run counters. ACTIVE damage never ends while a BEGIN contributor is missing (verifier's scenario: the slave that saw the damage rebooted, END fired 40 superframes later on the other slave alone); INACTIVE, a member absent for a full P = 32 leaves the set, after which the remaining slaves' own P-run decides (a BEGIN takes about 2P after losing the low-drop slave instead of P). Dropouts shorter than 8 superframes are pooled over the rest, as in the evaluation (`stats.dmg_held` counts held superframes). A stale alarm persists until the contributor returns; there is no timeout. A recommissioning slave (COMMISSIONED false -> true after having been true, or f1_0 jumping by > 0.5 %) is announced with a `damage` line `"state":"BASELINE","slave":n` (informational). **f1_0, the AE normaliser/reference and the b baselines are RAM-only**: a slave that reboots on a damaged structure recommissions ON THE DAMAGED STATE and will report drop 0; persisting the baselines in NVS is hardware-day future work. (4d) `report_sanitize` runs only on ACCEPTED reports (after the stale/future/duplicate/unpolled checks), so `rx_ae_bad`/`rx_f1_bad` never count rejected reports. ## Interactive digital twin (viva demo, simulation only)
- `tools/twin_server.py` (`TwinCore` = state, timeline, netsim runs, prefix check; `TwinServer` = MQTT + real-time pacing; `parse_command` strict validation, `RateLimiter` 1 per 2 s). Holds a building (default seed 5,990,011, floors 5/10), the current damage `(storey, loss)`, killed slaves and transient overlays (impact 12 sf, 3x shake 12 sf). A command takes effect from `published sf + 4` (`GUARD_SF`): the timeline (`Timeline`: frozen `Seg` pieces, cached renderings, fresh exc ids from 1000, impact exc 2, shake exc 16) is truncated there and the future rebuilt under the new state, netsim (`.pio/build/netsim/program.exe --traces --events-jsonl --superframes N` plus `--kill/--revive node:sf` from the kill history; scratch `.cache/twin/<site>/`) is re-run over the whole history + 150 sf look-ahead, the lines already published must be byte-identical (`TwinCore.warnings` / stderr otherwise) and publishing continues after the last one. Paced by `t_us` / `--speed` (default 2; 0.1-200, no unpaced mode). Commands are refused until sf 100 (commissioning). Reset = healthy, all sensors revived, overlays cancelled (baselines kept; a revived sensor recommissions on the CURRENT structure).
- Topics: the sim_publisher line topics + retained `twin/state` (running, speed, sf, commissioned, building f1, damage, `f1_true_hz`, `drop_true`, killed, `truth` = [[sf, t_us, f1]], last_cmd, log tail), `twin/log` (one line per applied/ignored command, sent before the netsim re-run), `twin/cmd` (input, retained commands ignored). Default site = new random `twin-xxxxxxxx`. Anyone knowing the site can command it (public broker, simulated data only).
- Hardening (b5adbd7): commands need >= 6 superframes spacing (`too soon ... wait N more superframes` twin/log line), at most ONE pending command (busy / rate-limit log lines, receive-time 1 per 2 s), non-finite command fuzz refused, SIGTERM / SIGBREAK / Ctrl+C publish `running:false`, `twin/state` carries a heartbeat `updated_t` (wall-clock s) + `period_s` (5) and is republished every 5 s; the netsim re-run can pause publishing 1-3 s after a command. A KILLED server leaves a stale retained state: the dashboard detects it (alive = running AND heartbeat < 3 periods old / live state seen) and then shows 'twin stopped / not responding', disables the buttons and hides the truth band.
- Dashboard: `twinCard` panel (shown on a connected MQTT source with a valid `twin/state`; `sanitizeTwin` validates every field, `onTwin`/`renderTwin` are try/catch-wrapped, hidden on disconnect / file load), `onTwin/renderTwin/twinSend`, dotted `steps` line on the f1 chart (`drawChart` option `steps`). Tests: `tools/test_twin.py` (24 checks, offline, needs netsim), `node dashboard/tools/test_mqtt_dom.js --twin` (jsdom + real broker). Runbook: `docs/demo_runbook.md` (f).
## data/
- `generator/generate.py` – synthetic dataset (numpy+pandas, seed 42, FS=100, N=128). 50 recordings/class x 40 non-overlapping windows -> 6000 windows of raw int16 counts. normal: f0 4-12 Hz, small amp; abnormal: higher amp + envelope growth/drift; faulty: f0 shift to 14-30 Hz and/or damped-sinusoid impact spikes. Features per axis: rms (raw, incl. DC), std (mean-removed), excess kurt, domfreq (rfft argmax, DC excluded). Prints class balance + stats.

## models/
- `training/train.py` – Phase 3 selection (~1 h runtime). 18 inputs `{axis}_{std,kurt,domfreq}` (rms excluded: DC/offset dependent). Fixed holdout 10 rec/class (SEED=42; the discarded `rng.permutation(dev)` call must stay, it keeps the holdout draw stable), 10x repeated grouped 5-fold on dev, grid DT/RF/MLP, RF scored by hard vote. Rule: smallest footprint (10 B/node) among configs <=5120 B with all 10 repeat means >=0.90. Also broad resampling, offset test, export.
- `training/compare.py`, `training/compare_svm.py` – post-selection comparison of 18 DT/RF + 6 SVM configs vs dt_d3 under the same broad resampling (200 holdout re-draws, 40x grouped 5-fold on all 150 recordings), pre-registered replacement rule. Outputs `selected/comparison/`.
- `training/dlpf_check.py` – emulates the MPU6050 DLPF (upsample to 1 kHz, causal filter, read every 10th sample) on the dataset and reports prediction flips; output `selected/validation/dlpf_check.json`.

- `training/fusion_eval.py` (R2, first criterion, superseded) – evaluates the 21 fusion candidates (rules a-d x T {1.5, 2, 3} x tree variant) per superframe on simulated buildings, scored once on seeds 5,200,000+ (bootstrap by building, primary pair 5/10 and secondary 3/7, degraded mode, uninstrumented floor, isolated impacts); also holds `RefFusion`, the bit-exact scalar reference of fusion.h (with debounce).
