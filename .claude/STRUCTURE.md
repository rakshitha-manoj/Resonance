# Resonance structure

Edge structural health monitoring: ESP32 + MPU6050 classifies vibration as normal / abnormal / faulty.
Targets: >=90% accuracy, <50 ms inference, model <100 KB.

## firmware/esp32/ (PlatformIO project, open this folder in VS Code for PlatformIO + Wokwi)
- `platformio.ini` – four envs, all with `-ffp-contract=off`: `esp32dev` and `selftest` (espressif32, Arduino, electroniccats/MPU6050@^0.6.0, 115200 baud), `native` and `netsim` (host builds, need WinLibs gcc on PATH). Details on the envs line below.
- `wokwi.toml` – points Wokwi at `.pio/build/esp32dev/firmware.bin` / `.elf`
- `diagram.json` – ESP32 DevKit v1 + MPU6050 (SDA D21, SCL D22, 3V3, GND), UART0 -> Wokwi serial monitor
- `platformio.ini` envs: `esp32dev` (live, `build_src_filter = -<*> +<main.cpp>`, an explicit list so new host-only sources like netsim_main.cpp are not pulled in), `selftest` (src/selftest.cpp only), `native` (host Unity test, `test_filter = test_native`; needs WinLibs gcc on PATH), `netsim` (host: builds `src/netsim_main.cpp` CLI; `pio test -e netsim` runs `test/test_net`). All envs `-ffp-contract=off` (no FMA so ESP32 float rounding matches x86).
- `src/main.cpp` – live inference: 10 ms micros() deadlines, DLPF 42 Hz, boot read-back of DLPF/accel/gyro config (`config fail` halts), buffers az+gx (128 each, non-overlapping, schedule re-anchored after each window), 2-of-3 smoothing, prints `window,class,state,feat_us,tree_us,span_us`. (Phase 1 raw CSV streaming is in git history.)
- `src/selftest.cpp` – boot self-test: 606 embedded dataset windows (class + feature diffs, latency), then a 120-window scripted sequence (normal→faulty→normal→abnormal→normal→normal-with-isolated-error) checking raw class and smoothed state vs Python; ends `seq done PASS/FAIL`.
- `include/smooth.h` – `smooth_update(hist, raw, state)`: state becomes a class once it has 2 of the last 3 raw windows, else holds. hist starts {-1,-1,-1}, state 0.
- `include/features.h` – feat_std_kurt / feat_std / feat_domfreq (two-pass float32, direct DFT bins 1..64), `features()` computes only the 5 used features, `classify()`.
- `include/model.h` – GENERATED by `tools/gen_model.py` from models/selected/model_export.json (if/else tree, hex-float thresholds, DFT twiddle tables).
- `tools/gen_testdata.py` – writes `test/data/windows.bin` (all 6000 windows), `test/data/smooth.bin` (2592 smoothing sequences: exhaustive length ≤6 + OOF) and `include/selftest_data.h` (606 windows + scripted sequence); all gitignored, need dataset.csv.
- `test/test_native/` – host tests: all 6000 windows vs Python predictions, and smoothing vs Python reference (`pio test -e native`).
- `selftest/wokwi.toml` + `diagram.json` – Wokwi config for the selftest build (select via "Wokwi: Select Config File").
- `include/net_proto.h` – 3-node network protocol (R1, wire VERSION 2): ALL timing constants (superframe 1.4 s, poll start 1.32 s, reply timeout 18 ms, one retry, DEAD after 3 missed superframes, beacon grace/limit, `MAX_SF_JUMP`), CRC-16/CCITT-FALSE, header + BEACON (17 B: sf, master epoch) / POLL (18 B: sf, epoch, attempt) / SLAVE_REPORT (44 B: sf, epoch, window, raw, state, flags, 5 floats) encode/decode (memcpy, little-endian, CRC and exact length checked), static asserts on size and on polling fitting in the superframe. Report flags: LOW_SIGNAL, UNSYNCED (other bits reserved => master rejects).
- `include/transport.h` – abstract broadcast send (`net::Transport::broadcast` returns `bool`: false = send failed, callers count it); ESP-NOW later.
- `include/tiers.h` – portable state machines, no Arduino/no heap/no platform calls: `SlaveNode` (beacon -> window request -> `deliver_window(token, ...)` -> cached report, answers POLL only when ready and the epoch matches, noise gate `NOISE_GATE_COUNTS` provisional and applied BEFORE smoothing, free-runs/UNSYNCED up to 5 missed beacons then LOST) and `Master` (`reset(start_us, epoch)`, beacon on a fixed grid, poll slave 1 then 2 with one retry, dedupe/stale/epoch/field/polled-source rejection, DEAD/ALIVE events, `MasterListener` hook for report/status where R2 attaches fusion). See "Network behaviour" below.
- `include/netsim.h` + `src/netsim_main.cpp` – deterministic discrete-event simulator of master + 2 slaves (own PRNG; i.i.d. loss, delay, jitter, corruption, kill/revive of any node incl. the master (= restart with a fresh epoch) at a superframe or any microsecond, send failures, master tick lateness, compute time, pluggable `WindowSource`); CLI prints one line per event (not with `--quiet`) and a summary. Run: `pio run -e netsim` then `.pio/build/netsim/program.exe --loss 0.2 --kill 0:12 --revive 0:12 --kill 1:20 --revive 1:30` (`pio test -e netsim` writes the test runner to the same `program.exe`, so run `pio run -e netsim` again after testing). `SimConfig::master_stall_from_us/until_us` blocks the master host for a test. LIMITS: no collisions, carrier sense or airtime; loss is i.i.d. per link (real loss is bursty); `SimResult::audit()` recomputes the invariants.
- `test/test_net/` – Unity tests for protocol (incl. valid-CRC wrong-length/type frames), noise gate, slave (sync, epoch, jump window, token, tx failure), master (validation, polled-source, grid, skip-forward, restart), simulator and its invariants, master restart recovery at sf 10/50/200, tick lateness, master host stalls (`pio test -e netsim`, 57 tests).

## Network behaviour (R1) – read before touching tiers.h
- Master epoch: `Master::reset(start_us, epoch)` takes a boot epoch (random on hardware, e.g. `esp_random()`, different from the previous boot; PRNG in the simulator). It is carried in every BEACON, POLL and REPORT. The master drops reports of another epoch (`rx_epoch`); a slave answers only polls of its current epoch.
- Slave sync rules: power-on or LOST => any CRC-valid beacon is accepted. Synced and epoch changed => resync at once (new epoch, window in progress abandoned, cached report discarded; smoothing history, smoothed state and window counter are KEPT because they describe the slave's own sensor, so the first post-restart report is just window N+1). Synced, same epoch => `sf` must be in (last, last + `MAX_SF_JUMP`], `MAX_SF_JUMP` = 8 = `MAX_MISSED_BEACONS` + 3 (free-running advances last_sf, so a legitimate beacon is at most +1; 8 leaves slack yet keeps one stray CRC-valid beacon from locking a slave out); sf == last right after a free-run is a late beacon (timing re-aligned, running window kept; the window keeps UNSYNCED, because it was started on the slave's own timing and the flag is the only field evidence for tuning BEACON_GRACE_US). A CRC-valid forged beacon with a new epoch is adopted, but the real master's next beacon changes the epoch again and resyncs the slave.
- Restart recovery (simulator, lossless): first fresh report 1.32-1.33 s after the master restarts (within one superframe; every restart offset within 0.95 superframes in re-verification), no stale report accepted. 20% loss: usually within 2 superframes, but the tail is longer: 1.6% of 1600 slave-runs took 3 or more, worst about 7 superframes (~9.7 s), because a lost first beacon after the restart leaves the slave free-running in the old epoch. No foreign-epoch or stale report was accepted.
- Epoch reuse: if a restart reuses the previous epoch, the slaves see an sf far behind theirs and reject beacons until they go LOST (about 6 superframes outage, DEAD/ALIVE events, no stale data). The `Master` constructor uses epoch 0, so real firmware MUST call `reset(..., e)` with `e = esp_random()` taken after Wi-Fi start, rejecting 0, never a timer-derived value.
- Window token API: `uint32_t token = take_window_request()` (non-zero; 0 = nothing requested), `window_start()`/`window_sf()` for the window's first-sample time and superframe, `bool deliver_window(token, az, gx, now)`. A window abandoned by a later beacon or by `reset()` has a different token (the counter survives `reset()`), so its late delivery is rejected (`windows_rejected`) and changes nothing.
- Master beacon schedule: fixed grid (`next_beacon_ += SUPERFRAME_US`), not `now + period`, so tick lateness does not accumulate (mean period stays 1.4 s). If a tick is a whole superframe or more late the master sends one beacon, jumps to the next grid point after now and counts the skipped points (`beacons_skipped`); the superframe number advances by the skipped points too, so it stays equal to the grid index and stays in step with slaves that free-ran through the stall (without this, a 2.8-8.5 s master stall made the slaves reject its beacons as stale: false DEAD on both, or a stale report accepted; `test_sim_master_stall` covers 0.5-9 s stalls). Polling start is still `beacon time + 1.32 s`. Measured with the master woken 0-8 ms late on every wakeup (1500 superframes): mean period 1,400,000.2 us, 3000/3000 reports, no DEAD, no overrun; BEACON_GRACE_US (5 ms) is below that lateness, so 7.8% of windows start via a false free-run (at most ~3 ms from the beacon transmission in re-verification; harmless to classification) and all of them arrive flagged UNSYNCED. Real tick lateness should be well under 5 ms; measure on hardware.
- Report validation at the master: raw class or state outside {0,1,2}, reserved flag bits, non-finite feature => `rx_bad_field`; source must be slave 1..2 (`rx_invalid`); a report is accepted only from a slave the master has polled in the current superframe (`rx_unpolled`; a late reply to an earlier poll of the same superframe is fine) and only while polling is open. Real MAC/authentication checks come in R5.
- Send failures: a failed `broadcast` is counted (`tx_failed`). Master: a failed poll counts as a used attempt and the retry / next slave follows immediately; a failed beacon makes the slaves free-run. Slave: a failed reply is counted, the master's retry asks again.
- Compute-time limits (timing constants are NOT to be changed before hardware measurements): slave 1's first poll fails above ~50 ms compute (~45 ms on the free-run path), and slave 1 is declared DEAD while healthy from ~68-70 ms; slave 2 tolerates ~100 ms. The measured on-device feature time (~24 ms in Wokwi) is inside this, but re-check on hardware.
- False DEAD: with the 3-miss rule and 2 attempts, a healthy slave is declared DEAD about 0.1 times per slave-hour at 10% i.i.d. loss and about 5 per hour at 20%, so the rule suits only low loss. R5 must measure real loss and its burstiness before choosing DEAD_AFTER_MISSES.
- Hardware notes for the ESP-NOW port: use a 64-bit clock (`esp_timer_get_time()`), never 32-bit `micros()` (wraps after 71 min and breaks the 64-bit deadline arithmetic); the ESP-NOW receive callback runs in the Wi-Fi task, so queue received packets to the main loop and call `on_packet` there, because the state machines are not thread-safe; check `Transport::broadcast`'s return value (esp_now_send queue full/error => false).

## data/
- `generator/generate.py` – synthetic dataset (numpy+pandas, seed 42, FS=100, N=128). 50 recordings/class x 40 non-overlapping windows -> 6000 windows of raw int16 counts. normal: f0 4-12 Hz, small amp; abnormal: higher amp + envelope growth/drift; faulty: f0 shift to 14-30 Hz and/or damped-sinusoid impact spikes. Features per axis: rms (raw, incl. DC), std (mean-removed), excess kurt, domfreq (rfft argmax, DC excluded). Prints class balance + stats.
- `processed/dataset.csv` (gitignored, regenerate with `.venv/Scripts/python data/generator/generate.py`): recording_id, label, ax_0..gz_127 (768), 24 features `{axis}_{rms,std,kurt,domfreq}`. Train/test must split by recording_id.

## models/
- `training/train.py` – Phase 3 selection (~1 h runtime). 18 inputs `{axis}_{std,kurt,domfreq}` (rms excluded: DC/offset dependent). Fixed holdout 10 rec/class (SEED=42; the discarded `rng.permutation(dev)` call must stay, it keeps the holdout draw stable), 10x repeated grouped 5-fold on dev, grid DT/RF/MLP, RF scored by hard vote. Rule: smallest footprint (10 B/node) among configs <=5120 B with all 10 repeat means >=0.90. Also broad resampling, offset test, export.
- `training/compare.py`, `training/compare_svm.py` – post-selection comparison of 18 DT/RF + 6 SVM configs vs dt_d3 under the same broad resampling (200 holdout re-draws, 40x grouped 5-fold on all 150 recordings), pre-registered replacement rule. Outputs `selected/comparison/`.
- `training/dlpf_check.py` – emulates the MPU6050 DLPF (upsample to 1 kHz, causal filter, read every 10th sample) on the dataset and reports prediction flips; output `selected/validation/dlpf_check.json`.
- `training/smoothing_eval.py` – 2-of-3 smoothing evaluated on out-of-fold predictions (false alarms, spurious changes, detection/recovery delay, accuracy with and without transition lag); output `selected/validation/smoothing_eval.json`.
- `selected/` – deployed model = dt_d3 retrained on all 150 recordings: `model.joblib`, `model_export.json` (11 nodes, float32 thresholds, go left if x <= t), `feature_spec.json` (inputs, used features, formulas, MPU6050 ±2 g / ±250 °/s, exact 100 Hz timer sampling), `report.json`/`report.md` (headline ~0.93 broad resampling; selection history v1→v4), `comparison.md` (no alternative qualified; fallback rf_n50_d4).
